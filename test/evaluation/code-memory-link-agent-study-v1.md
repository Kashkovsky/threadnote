# Code Memory Link post-release agent study v1

Status: proposed analysis contract. Freeze the exact bytes and reviewed subject/harness identities before a new calibration or canonical trial. This study does not change the existing release scorer.

## Question and design

Does an explicit current code anchor increase a coding agent's chance of retrieving the task's gold cited memory, compared with a task-only Context Brief, under identical task packets and budgets? Does any retrieval gain survive into correct use and task completion without harming negative controls?

Use the sealed suite's 12 hidden tasks (five lexical and seven anchored-only) and 16 negative controls, two predeclared client configurations, and three blinded arms: anchored v3, task-only v2, and no-memory. Each client/task block has all three arms; the existing seeded, counterbalanced schedule contains 168 assigned cells. The finite suite is the study population. Token-renamed replicas within a scenario family are not independent samples from all software tasks.

The evaluated Threadnote executable is an exact released subject with recorded source commit, version, executable SHA-256, and dependency/runtime identity. The clean harness-governance commit is recorded separately. Neither may change after preparation. The canonical run uses a new private root, new random seeds, a reviewed manifest and assignment, and exact reviewed client descriptors.

## Outcomes fixed before the run

The primary outcome is **assigned-trial gold retrieval** on each hidden cell. It is one only when replay of the retained app-server evidence finds the canonical, successful Context Brief call before qualifying action, the call matches the sealed gold citation, and the trial adheres to its assigned arm protocol. A missing call, failed call, invalid call, wrong citation, or gold citation appearing only after qualifying action is zero. No-memory is a negative manipulation check, not the primary comparator.

Evidence replay retains a completed agent trial with zero, failed, or repeated Context Brief calls as protocol noncompliance; it still rejects any successful response whose hash differs from the sealed arm. The existing release verifier may continue requiring exactly one successful call. Study analysis and any private study bundle must use the replayed trial/evidence ledgers and this study contract, not the release-pass verifier or its quality-filtered retainer.

The primary finite-corpus contrast is anchored minus task-only success rate over the 24 matched hidden client/task blocks. Report both arm counts/rates, the paired win/loss/tie table, the absolute percentage-point difference, and the same quantities by client and by lexical versus anchored-only family. The prespecified practically relevant improvement is at least three net additional anchored successes across 24 blocks (12.5 percentage points, the first attainable increment above 10 points), a positive difference in the anchored-only family, and no negative difference in either client or the lexical family. This is a finite-suite decision rule, not a population significance test.

The mechanism check is gold retrieval among _valid assigned-arm Context Brief calls_, with its denominator, plus assigned-trial call rate and protocol adherence. It cannot replace the intention-to-treat primary outcome. Secondary outcomes are adjudicated useful-memory use, qualifying action, exact task pass, hidden-constraint adherence, steps/tokens to first useful use with no-use censoring, and total task steps/tokens. Report task pass by arm, client, and family, including when primary retrieval improves but correct action does not. The existing stricter release gate remains separately reported and cannot be called passed by this study's retrieval rule.

Safety outcomes are accepted stale/harmful instruction count and paired negative-control regressions against no-memory, by family and client. A clean safety result requires zero accepted stale/harmful instructions and zero negative-control blocks where a memory arm fails while no-memory passes. If safety fails, report the retrieval effect but do not describe the intervention as safe or ready for release. Do not silently exclude protocol failures from any assigned-trial denominator.

## Missingness and uncertainty

The primary contrast is assessable only when all 168 scheduled cells have one replayable validated completion and there are no unacknowledged, failed, interrupted, or retried governed attempts. A completed agent trial without a valid call contributes zero retrieval. If an infrastructure stop leaves cells unstarted, publish the observed prefix, the cause, and best/worst-case bounds for the unobserved assignments; do not report a primary pass. A newly sealed attempt requires a new manifest and seeds. Never retry a failed outcome into the original ledger.

Report the finite-suite paired contrast without a p-value or population confidence claim. Provide task-clustered descriptive spread as a sensitivity analysis, treating the two client configurations for one task as one cluster. State the small suite, one run per configuration/arm/task, model stochasticity, shared client implementation, task construction, and any time drift as limitations. Do not use an exploratory interval to override the prespecified decision rule.

## Calibration gate and sequence

Use only the separately hashed two-task calibration corpus. Before examining its new outcomes, record the exact subject/harness/client identities and the calibration plan hash. Proceed to the 168-cell study only if all 12 calibration cells finish without a terminal process failure, at least 10/12 adhere to their arm protocol, anchored gold retrieval is at least 3/4 on assigned calibration cells and strictly exceeds task-only assigned-trial gold retrieval, and harmful acceptance remains zero. Correct action is recorded but is not a go criterion for this retrieval-primary study. Preserve every calibration iteration and negative observation; no calibration cell becomes canonical evidence.

Before preparation, run focused parser/replay/scorer tests, schedule and provenance properties, privacy scans, and PR CI on the reviewed harness. Independently review the fresh manifest and assignment, then record the exact manifest approval in a governance-only commit. Run the matrix once, sequentially, and retain the attempt, evidence, and trial ledgers. Independently replay every outcome, run exact-build dogfood and applicable scale checks, retain a privacy-scanned content-addressed bundle, and write the article's result and limitations sections from verified aggregate evidence. The article draft stays outside Git.

No claim is contingent on favorable results. Completion includes a null or negative finding if the frozen protocol was executed and analyzed honestly.
