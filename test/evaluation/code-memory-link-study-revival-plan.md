## Study decision to freeze before evidence

The next study should ask whether code anchors cause a coding agent to **retrieve the right memory**, then measure whether the agent uses that memory correctly. Record the old task-success preregistration and its weak calibration as a superseded study design, with the reason and dates; never reinterpret its outcomes as a successful trial.

Preregister a versioned post-release analysis contract before looking at any new canonical outcome:

1. Primary endpoint: intention-to-treat gold-citation retrieval on assigned hidden tasks, anchored v3 versus task-only v2. A missing call, failed call, or wrong citation counts as no retrieval. Set the finite-corpus improvement threshold and task-cluster analysis before the run.
2. Mechanism check: gold retrieval conditional on a valid Context Brief call, plus protocol adherence and the fraction of assigned trials that call the tool. Keep this distinct from the primary endpoint.
3. Secondary endpoints: adjudicated useful-memory use, correct action, task pass, first-use provider steps/tokens, total usage, and per-client/per-scenario-family results. Report these even when they contradict retrieval gains.
4. Safety: preserve zero accepted stale/harmful instructions and the negative-control no-regression checks. Predeclare how missing/failed trials enter every denominator. Do not claim population confidence from token-renamed task replicas; use independent scenario clusters for any uncertainty analysis.

Keep the existing release scorer unchanged as a separate, stricter claim. If a new science scorer is needed, version it and test its parsing, missingness, schedule integrity, and arm-blind calculations before sealing the study. A study with better retrieval but poor action is a valid negative result for downstream utility, not a release-gate pass.

## Execution sequence

1. **Audit and isolate.** In this worktree, compare the merged PR #344 harness against its final reviewed contract; preserve the old calibration aggregate without importing it into canonical ledgers. Keep dependency, lockfile, release, and global-install changes out of this branch while the parallel patch release is active. After that release lands, refresh this worktree and verify the Codex adapter, model configurations, auth boundary, Bun, and exact candidate runtime against its final dependency/runtime set. Choose a signed released Threadnote subject only then and record source SHA and executable SHA. The current global development binary belongs to the patch-release worktree and must not silently be replaced.
2. **Repair only the measured failure mode.** Use the separate calibration corpus to diagnose why agents that retrieved gold failed to act. Inspect only bounded, privacy-safe event classes. Add a closed decision/action class only if it changes adjudication. Keep calibration prompts and fixtures out of the 28-task sealed corpus. Add focused tests and bounded properties for any changed protocol invariant; run focused checks and PR CI. Follow the repository exact-HEAD global-install and ownership rules if a runtime-facing change is made.
3. **Freeze the analysis and pilot.** Review the endpoint hierarchy, finite-corpus effect threshold, missingness rules, scenario-family coverage, sample-size rationale, client roster, budgets, and go/no-go criteria before a fresh calibration. Run that calibration on new seeds and keep all failures. Proceed to the canonical matrix only if the retrieval manipulation and tool-call transport are credible; weak action alone does not invalidate a retrieval-primary study, but limits its expected claim.
4. **Preregister anew.** Prepare a fresh, private, content-addressed 28-task, two-client, three-arm schedule (168 cells) using the exact subject and clean reviewed harness-governance commit. Independently review the manifest, assignment, sealed fixtures, client descriptors, source/build hashes, arm discrimination, and privacy inventory. Add only the new manifest hash in the reviewed approval commit required by the current protocol. Do not reuse historical seeds or approvals.
5. **Run once, sequentially.** Execute the frozen schedule with the governed matrix and exact executable. Preserve attempt, evidence, and trial ledgers; never silently rerun failed or interrupted attempts. Stop and classify any infrastructure failure according to the preregistered recovery rule. Do not edit the analysis contract after outcomes become visible.
6. **Analyze and retain.** Independently replay the ledgers and score primary, mechanism, secondary, and safety endpoints, including failures and missing calls. Run the six-case exact-build dogfood and the applicable deterministic/hosted scale checks for the frozen subject. Produce a privacy-scanned, content-addressed retained bundle and a reviewable methods/results report with all artifact hashes, deviations, failure observations, effect sizes, and limitations. Use an isolated governance branch/PR for approvals and evidence; do not couple this post-release study to a product tag.

Completion means the frozen matrix has been run or stopped under its prespecified rule, its evidence has been independently replayed, and the report states the supported claim even if the result is null or negative. It does not mean making the existing release gate pass by weakening it after the fact.
