## Evidence lanes

The evidence is intentionally split by workload. Timings from different lanes are never combined into a synthetic
percentile or a portable SLA.

| Lane               | What it establishes                                                                                                                                                           | Retention                             |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| PR CI              | Full correctness, platform packaging, focused 10k/100k cold and one-file graph budgets                                                                                        | GitHub checks and benchmark artifacts |
| Production-large   | One exact-SHA, pinned-runner observation with cold, one-file overlay, independent clean rebuild, per-phase CPU/RSS/bytes, storage, parity, and bounded Manager/query evidence | 90-day artifact                       |
| Heavy tail         | Parser/cache behavior for duplicate blobs, low-signal JSON/SVG, large TypeScript, interruption/resume, and deterministic one-versus-four-worker output                        | 90-day artifact                       |
| Focused properties | Lifecycle convergence/protection, incremental equivalence, ranking, removal idempotence, and fair workset allocation                                                          | Normal Vitest suite                   |
| Installed runtime  | Exact clean-HEAD installation and affected-flow smoke on the development host                                                                                                 | Active Threadnote handoff             |

The pushed implementation candidate dispatched Platform benchmarks run
[`31350688922`](https://github.com/Kashkovsky/threadnote/actions/runs/31350688922) with production-large and heavy-tail
coverage enabled. PR #131 supplies the ordinary required checks for the same candidate. Exact-tag production-large
evidence starts again automatically after `v4.1.0-beta.1` is pushed; release publication does not misrepresent that
bounded `n=1` observation as a universal latency claim.

That first run measured `3b7c52c270702d497f01a1179f8b436cb4ac6657` and exposed four stale harness/platform
contracts now corrected by `46fb831`:

- vector positive controls still required the pre-M7 documentation score instead of applying the public relevance
  policy;
- Windows completed the graph gates but briefly retained closed SQLite handles during owned temporary-directory
  cleanup;
- the heavy-tail harness expected metadata symbols/cache facts for JSON/SVG classes that H1 now excludes before
  admission; and
- MCP completion logging allowed only 50 ms on Windows, so a returned tool error could lose its privacy-safe finish
  record.

The same run retained a production-large checkpoint after the measured phase reached its 20-minute boundary during
materialization. Artifact
[`9049165643`](https://github.com/Kashkovsky/threadnote/actions/runs/31350688922/artifacts/9049165643), SHA-256
`8f43f2b1d7c77ea26685fd9e7f02c0eba863cd8a91aa9812fdb1980ce5dae27e`, records 73k-fixture scanning and
materialization telemetry rather than a completed end-to-end sample. Peak observed RSS was about 1.43 GB during
scanning and 749 MB during materialization; the main SQLite file reached about 4.26 GB while materialization was still
running. This is a failed strict evidence boundary, not a performance pass. The timeout was not extended, and the beta
makes no maximum-performance claim. Fresh candidate CI and heavy-tail evidence are required for `46fb831` and its
release-metadata successor before merge.

## Release gates

The beta is eligible only when required PR checks are green and the retained evidence reports no:

- omission of manifest-declared active source;
- repository path, source content, credential, or local-root leak;
- unbounded writer wait or abandonment of a lock-verified live owner;
- cross-worktree graph contamination or loss of the prior ready snapshot on failure;
- full-repository rewrite for a proven one-file closure;
- unsafe low-disk continuation or non-converging removed-worktree storage.

These are correctness and containment gates. “Maximum performance” means the measured profile exposes no known
dominant bottleneck that is being hidden by a timeout increase. It does not mean every repository or machine will
observe the same wall time.

## Deliberate boundaries

- The production-large artifact is `n=1` on a pinned runner. Trend claims require multiple retained runs on the same
  runner class.
- The public surrogate preserves reviewed shape and privacy-safe controls; private exact-repository evidence remains
  private and is summarized only through aggregate, path-free observations.
- Workset queries inspect existing ready snapshots only and never fan out cold builds.
- Mobile resource extraction indexes textual identifiers and explicit wiring, not pixels, visual semantics, or binary
  asset contents.
- Optional vectors remain a separate readiness phase; structural graph availability is the release-critical boundary.
